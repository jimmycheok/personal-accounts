# Release v2.6 — Mileage Becomes a Logbook, Voucher PDF Fixes

**Date:** 2026-08-11
**Branch:** release/v2.6
**Base commit:** 239fd8c

## Summary

Two corrections, both found by comparing what the code did against what the documentation claimed.

**Mileage is no longer a deduction.** Logging a trip previously posted `DR 6400 / CR 3000 Owner's Capital` at `km × rate`, so mileage claims and actual vehicle receipts both fed Borang B **D5** — and both were being claimed, double-counting the same driving. LHDN publishes no per-km rate for a sole proprietor; the statutory basis under **s.33(1) ITA 1967** is actual costs apportioned by business use, substantiated by a logbook. Mileage is now exactly that: a trip record and an on-screen estimate, posting nothing to the ledger. D5 comes solely from receipts in the Expenses module.

**The payment voucher PDF rendered a literal `{{business.address}}`** and carried unwanted signature lines. `BusinessProfile` has no `address` field, and `renderTemplate` never visits a placeholder naming a field that does not exist — so it survived into the document.

This supersedes v2.5's `6410` account split, which never deployed. With only one basis there is nothing to separate, so the account and its seeder were removed.

## Spec Changes

- **Mileage posts no journal entry and produces no deduction.** `deductible_amount` is still computed and stored, but is an estimate for reference only. D5 is sourced entirely from expense-account receipts.
- **Account `6410` Mileage Claim is removed**, along with its seeder. A fresh install seeds **40** accounts.
- **`GET /taxation/borang-b` no longer returns `mileageOverlapMonths`.** `mileage: { totalKm, deductibleAmount }` is unchanged and remains display-only.
- **`LedgerQueryService.getMileageOverlapByMonth` removed.**
- **`PdfService.renderTemplate` now strips unresolved placeholders** and warns. Dynamic sections use `<!-- ... -->` markers replaced afterwards and are unaffected.
- The payment voucher PDF no longer carries signature lines.

## Upgrade Notes

**No new seeders and no migrations.** The `6410` seeder is deleted; if a prior deploy created that account it becomes an unused empty row — harmless, and this release does not remove it retroactively.

**Run the mileage cleanup after deploying.** Existing mileage journal entries remain deductions until removed:

```bash
docker compose -f docker-compose.prod.yml run --rm api \
  node scripts/remove-mileage-journal-entries.js          # dry run first
```

Back up the database first — the deploy script does this automatically. The script never touches `mileage_logs`; those trip records are the logbook substantiating the actual-cost claim and must survive.

> ⚠️ **This changes a tax figure.** On the current production data it removes 21 entries totalling RM1,334.52, moving D5 from RM1,971.52 to RM637.00 and Borang B `totalExpenses` from RM5,128.81 to RM3,794.29. That *raises* taxable income unless the missing vehicle costs are captured — there are currently no fuel, insurance, road tax or servicing records against roughly 2,224 km of logged trips. Captured properly, actual costs would likely exceed the previous figure. Confirm the basis with a tax agent before filing.

**Known limitation, unchanged:** `TaxCalculator.getMileageDeduction` computes its display figure at a flat RM0.25/km while the logs store `km × 0.60`, so the two disagree on screen. Pre-existing and out of scope; tracked in `docs/development-plan.md`.
