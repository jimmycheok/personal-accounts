# Release v2.3 — Payment Voucher Module

**Date:** 2026-07-24
**Branch:** release/v2.3
**Base commit:** 69b640e

## Summary
Adds an all-new **Payment Voucher (PV)** module for recording money paid out (primarily freelancer salaries). A voucher is created from a modal with a free-text **service-item** table and staged attachments. On save, the GL Review modal posts a **balanced double-entry journal entry immediately** — defaulting to DR Salaries & Wages (`6100`) / CR the payment-method account (Bank `1010` or Cash `1000`) — the voucher is assigned a `PV-YYYYMM-NNNN` number and marked posted. Vouchers produce a printable PDF (amount-in-words + signature lines) and can be voided to reverse the GL entry.

## Spec Changes
- **New tables**: `payment_vouchers` and `payment_voucher_lines`. Voucher lines carry a free-text `service_item` + `amount` only (no per-line GL account).
- **New routes** (all under `/api/v1/payment-vouchers`, behind `verifyJwt`): `GET /`, `POST /`, `GET /:id`, `GET /:id/pdf`, `PUT /:id`, `POST /:id/void`, `DELETE /:id`.
- **GL posting on create**: `POST /payment-vouchers` with a balanced `journal_lines` array posts the entry immediately via `JournalEntryService.createAutoEntry` (`source_type='payment_voucher'`), assigns `PV-YYYYMM-NNNN`, and sets status `approved`. There is **no separate approve step** (mirrors the Expense flow).
- **Void**: `POST /payment-vouchers/:id/void` reverses the GL entry (`deleteAutoEntriesForSource`) and sets status `voided`.
- **Default GL template**: `payment_voucher_create` in `GLReviewModal` → DR `6100` (Salaries & Wages, Borang B D2) / CR `1010` Bank, switching to `1000` Cash when the payment method is cash.
- **Attachments**: use the existing polymorphic `Document` model with `subject_type='payment_voucher'`.
- **PDF**: `GET /payment-vouchers/:id/pdf` renders a voucher via Gotenberg with itemized service lines, total, amount-in-words, and Prepared/Approved/Received signature lines.

## Upgrade Notes
- Run the two new migrations: `cd apps/api && npx sequelize-cli db:migrate`.
- No new environment variables. No seed changes (uses the existing Chart of Accounts — `6100`, `1010`, `1000`).
