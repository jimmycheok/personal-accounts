# Release v2.7 — Duplicate Payment Vouchers

**Date:** 2026-10-01
**Branch:** release/v2.7
**Base commit:** 07e75e0

## Summary

Payment vouchers can now be duplicated from the list, as invoices, expenses and mileage already could. A recurring payee — the same freelancer paid each month for the same service — no longer has to be retyped in full.

Review of that change surfaced two voucher bugs, both fixed here. The default voucher date was the **UTC** date, so in Malaysia a voucher created between 00:00 and 07:59 defaulted to yesterday — and on the 1st, to the previous month's PV number and GL period. Voucher lines also had no defined order, so the detail page, PDF and a duplicate could list service items differently from how they were entered.

## Bug Fixes

| Area | Fix |
|---|---|
| Voucher date | Defaulted to the UTC date — yesterday in Malaysia before 08:00. On the 1st that assigned the previous month's `PV-YYYYMM` number and posted to the previous month. Applies to New as well as Duplicate |
| Voucher line order | Lines came back in heap order (no `ORDER BY`), so detail, PDF and duplicate could reorder service items. Now ordered by `id` |

## Spec Changes

- **Duplicate copies** payee, bank, bank account, TIN, payment method, description, notes and every service item. **It does not copy** the date (resets to today), the payment reference (identifies the new payment), attachments, or the GL entry — the GL Review modal still runs on save.
- **Every payment voucher response returns `lines` ordered by `id` ascending** — `GET /payment-vouchers/:id`, the create/update/void responses, and the PDF.
- **`PaymentVoucherModal` accepts an optional `prefill`** (`{ ...formFields, lines }`). Without it, behaviour is unchanged.
- **The voucher's default date is the local date**, not UTC.

## Upgrade Notes

**No migrations, no seeders, no new environment variables.** The API and web images both change; `scripts/deploy.sh` rebuilds both.

**Known limitation:** the same UTC-date default remains in the expense, payment, invoice, quotation, mileage and journal-entry forms, and in the General Ledger, Account Ledger, Balance Sheet and Cash Flow date ranges. Fixed separately in `fix/local-date-defaults`.
